## Частина 1. Діагностика

| № | Що друкуємо | Що надрукувалося (До виправлення) |
| :-: | :--- | :---: |
| 1 | `a.equals(b)` | True |
| 2 | `unique.size` | 8 |
| 3 | `unique.contains(a)` | False |
| 4 | `stock.size` | 2 |
| 5 | `stock.contains(a)` | False |

* **Причина дефекту:** У класі `Product` було перевизначено метод `Equals()`, але не було перевизначено метод `GetHashCode()`.
* **Чому рядки 1 і 3 суперечать один одному:** Хеш-колекція спочатку обчислює `GetHashCode()`, щоб знайти кошик (bucket). Оскільки хеш-код не перевизначено, об'єкти `a` і `b` потрапляли в різні кошики за їхньою адресою в пам'яті, і метод `Equals()` для них навіть не викликався.

## Частина 3. Відповіді на питання за власним кодом

1. **Що саме ви додали в клас Product і з яких полів воно рахується?**
   * **Пояснення:** У клас `Product` було додано перевизначення методу `GetHashCode()`, який обчислюється виключно від поля `Code` (`Code.GetHashCode()`), оскільки саме артикул виступає унікальним ідентифікатором товару.

2. **Чому a.equals(b) повертало «так», а множина все одно вважала об’єкти різними?**
   * **Пояснення:** Множина `HashSet` шукає об'єкт у два етапи: спочатку за хеш-кодом шукає номер кошика, і лише всередині кошика порівнює елементи через `Equals()`. Через відсутність власних хеш-кодів об'єкти потрапляли в різні кошики, тому `Equals()` навіть не запускався.

3. **Що станеться, якщо порахувати хеш від поля name, а рівність лишити за code?**
   * **Пояснення:** Порушиться контракт між `Equals` та `GetHashCode`. Наприклад, два об'єкти з однаковим артикулом, але різними назвами (`Product("A-100", "Кабель USB-C")` та `Product("A-100", "Кабель Type-C")`), матимуть `Equals() == true`, але різні хеш-коди, через що вони знову потраплять у різні кошики й вважатимуться різними елементами.

4. **Чому поле name не входить у рівність і що зміниться, якщо його туди додати?**
   * **Пояснення:** Поле `name` — це описова назва, яка може змінюватися при перейменуванні, тоді як унікальність визначає артикул `code`. Якщо додати `name` у рівність, то один і той самий товар із різними назвами буде вважатися двома різними товарами й додаватиметься в множину двічі.
