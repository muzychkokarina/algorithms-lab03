# Лабораторна робота №15: Порядок залежностей

**Дисципліна:** Алгоритми та структури даних  
**Група:** ІПЗ-3/1  
**Мова програмування:** C#

## Мета роботи
Завершити готовий каркас топологічного сортування (алгоритм Кана) й застосувати його до двох наборів залежностей: робочого (Набір А) та зіпсованого з циклом (Набір Б), виявивши цикл через порівняння довжин без окремого обходу графа.

## Відповіді на контрольні питання

1. **Порівняйте свій порядок для набору А із сусідовим. Чи вони однакові? Назвіть пару предметів, яка в обох списках стоїть в одному й тому самому відносному порядку, і поясніть чому.**  
   Порядки можуть відрізнятися через різну черговість обробки незалежних предметів (наприклад, «Вступ» і «Математика»). Проте пара **«Вступ» та «ООП»** в обох списках завжди стоїть в однаковому відносному порядку («Вступ» перед «ООП»), оскільки існує пряма залежність і лічильник вхідних дуг «ООП» не може обнулитися раніше, ніж буде оброблено «Вступ».

2. **Для набору Б у результат не потрапили три предмети. Два з них утворюють цикл — назвіть їх. Чому третій теж не потрапив, хоча в циклі не бере участі?**  
   Цикл утворюють **«Бази даних»** та **«Вебтехнології»** (вони взаємно блокують один одного). Третій предмет — **«Курсовий»** — не входить у цикл, але залежить від «Вебтехнологій», тому його лічильник передумов ніколи не зменшується до нуля і він також залишається заблокованим.

3. **Чому ознакою циклу є саме довжина результату? І чому список предметів, що не потрапили в результат, не можна просто назвати «циклом»?**  
   В алгоритм потрапляють лише вершини без невиконаних передумов; за наявності циклу хоча б частина вершин ніколи не досягне лічильника `0`, тому довжина `order` буде меншою за кількість предметів. Набір необроблених вершин не є тотожним самому циклу, оскільки включає також усі «нащадки» циклу — вершини, що залежать від елементів циклу (як «Курсовий»).
